# Локальна перевірка Google → Home Assistant

## Один раз налаштувати Google

У Google Cloud створіть OAuth Client ID типу **Web application**, налаштуйте consent screen та додайте тестову пошту, якщо застосунок у режимі Testing. У **Authorized redirect URIs** додайте точну адресу:

`http://127.0.0.1:8095/accounts/google/login/callback/`

Якщо користуєтесь `localhost`, окремо додайте `http://localhost:8095/accounts/google/login/callback/`. Host, порт, шлях і кінцевий `/` мають збігатися. Для публічного сервера потрібна його HTTPS-адреса.

У локальному `.env` заповніть `GOOGLE_CLIENT_ID` та `GOOGLE_CLIENT_SECRET`; не надсилайте секрети в чат і не додавайте файл у Git. Перезапустіть Django. Реєстрація через пароль на публічному сайті вимкнена. Адміністратори входять через `/admin/login/` своїм наявним обліковим записом.

Сайт не отримує пароль Google. Нові Google-акаунти мають непридатний для локального входу пароль. Паролі старих локальних акаунтів і адміністратора Django зберігає як хеші, а не як відкритий текст. Автоматичне об’єднання старих акаунтів лише за поштою вимкнено; для першого тесту використайте нову пошту.

Офіційна документація: [Google provider django-allauth](https://docs.allauth.org/en/latest/socialaccount/providers/google.html).

## Підготувати другу машину Home Assistant

1. Скопіюйте `custom_components/anma_cloud` з `ANMA_HA_Integration_v0.3.0.zip` у `/config/custom_components/anma_cloud`.
2. Перезапустіть HA. Якщо ANMA вже є, не видаляйте інтеграцію.
3. Виберіть джерела, перевірте напрямки та збережіть прив’язки.
4. Знову відкрийте **Налаштувати**, у полі **Наступний крок** виберіть **Підключення сайту ANMA**, натисніть **Надіслати**.
5. Виберіть **Створити код на 15 хвилин**. Скопіюйте код і передайте власнику будинку приватно.

Код одноразовий, діє 15 хвилин. Перезапуск HA або створення нового коду скасовують старий. Код не зберігається сутністю чи в історії HA. Власник інтеграції може відкликати доступ у тому самому меню.

## Підключити через сайт — без термінала

1. Відкрийте `http://127.0.0.1:8095/login/` і натисніть **Продовжити з Google**.
2. У кабінеті **Мої будинки** натисніть **Додати будинок**.
3. Вкажіть назву, Tailscale IPv4 машини HA та код. Натисніть **Перевірити й підключити**.
4. Після підтвердження відкриється Live-огляд саме цієї машини.
5. Для іншої машини повторіть кроки з її окремим кодом. Будинки доступні у списку та в перемикачі огляду.

Для відновлення після відкликання створіть новий код і знову додайте машину **тим самим власником**. Сайт оновить ключ існуючого будинку, збереже ID та історію. Інший користувач не може перехопити зайняту станцію. Адміністративно призупинене підключення власник не може самостійно активувати.

## Мережа та ключі

Комп’ютер із Django має бути підключений до вашої Tailscale-мережі та мати доступ до HA на TCP 8123. Адреса в браузері залишається локальною. Код ANMA не є ключем приєднання до Tailscale: він підтверджує доступ до інтеграції на вже доступній машині.

Підтримується пряме HTTP-з’єднання з Tailscale IPv4 на порту 8123; шифрування мережевого трафіку забезпечує Tailscale. LAN IP, доменні імена, IPv6, довільні порти, HTTP redirects і системні проксі не використовуються. Якщо HA працює лише через HTTPS або інший порт, потрібна окрема конфігурація транспорту, якої в цьому локальному прототипі немає.

Обмежте Tailscale ACL: сервер ANMA → потрібні HA-машини:8123. Не відкривайте API інтеграції публічно; на HA endpoint доступний на його HTTP-інтерфейсах, а мережеве обмеження забезпечується firewall/Tailscale ACL. У `.env` можна додатково звузити дозволені адреси через `ANMA_ALLOWED_TAILSCALE_IPS`.

Код підтверджується HMAC-SHA256 із короткоживучим nonce/часом та відбитком ключа. HA зберігає лише SHA256 окремого ключа читання. Django зберігає сам ключ зашифрованим Fernet; `ANMA_CONNECTION_KEY` має залишатись стабільним і входити в захищену резервну копію разом із БД. Втрата ключа потребуватиме повторної прив’язки станцій. Повний HA Long-Lived Token не потрібен.

## Адмінка та історія

Для поточних показників: **Операційний центр → користувач → машини → Поточні параметри**. Посилання також є у списку користувачів і в картці користувача поруч із кожним його будинком. Сторінка опитує саме вибрану машину кожні 10 секунд, поки вкладка видима. Показує значення, одиниці та час зміни джерела. Якщо з’єднання відсутнє, показники очищаються; демо-підміни немає. Потрібні права staff та перегляду станцій; для списку машин користувача також потрібен перегляд користувачів. Superuser має всі ці права. Звичайні власники не отримують доступу до чужих станцій.

`/admin/`: пошук за поштою, назвою або IP; власники й кількість будинків; підтверджені підключення; час останніх даних; помилки; призупинення доступу через картку підключення. Ключі не показуються. Позначка «нещодавно на зв’язку» означає отримання даних за останні 5 хвилин, а не постійний фоновий ping.

Для нових підключень сайт накопичує знімки приблизно раз на хвилину, поки відкритий Live-огляд. Зберігаються останні 7 днів; графік показує 24 години, а пропуски позначені відсутністю даних. Стару історію Recorder цей протокол не переносить. Наявне підключення через `.env` зберігає читання історії HA.

## Межа виконаної перевірки

Автоматичні тести використовують ізольовану БД та локальний HTTP-сервер із справжніми обробниками інтеграції; середовище HA замінено тестовими об’єктами. Потрібна завершальна перевірка на вашій другій машині після встановлення ZIP та налаштування реального Google OAuth. Сам пакет не встановлює Tailscale, не створює OAuth-клієнт і не змінює віддалений HA.
